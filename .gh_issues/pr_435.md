## Description

This PR implements the "Multi-Stage Payroll Approval Workflow (Maker-Checker)" (Issue #435).

Previously, anyone generating a payroll would instantly commit it to the database as `finalized` and trigger payments/emails, which is a high risk in enterprise settings. This update introduces a strict approval state machine.

### Architectural Changes:
1. **Model Update**: 
   - Modified `PayrollUpdate` schema in `payroll.model.js` to include a `status` field with an enum `["DRAFT", "PENDING_APPROVAL", "APPROVED", "REJECTED", "paid", "pending", "failed", "finalized"]`.
   - Added `rejectionReason`, `approvedBy`, and `approvedAt` fields to maintain a tight audit trail.
2. **Controller/Routes Update**: 
   - `finalizePayroll` was refactored into `submitPayrollForReview`. Instead of sending emails, it marks the payroll as `PENDING_APPROVAL`.
   - Added robust `approvePayroll` and `rejectPayroll` controller endpoints.
   - Added `getPendingApprovals` to fetch all pending items.
3. **Frontend Integration**: 
   - Changed the "Finish & Pay" button on the Dashboard to "Submit for Review".
   - Built a sleek, brand new `Approvals.jsx` Dashboard page for Admins to review pending payrolls, displaying total sums.
   - Added quick-action "Approve" and "Reject" buttons. Rejecting triggers a modal to enforce providing a `rejectionReason`.
   - Integrated the "Approvals" view securely into the Sidebar navigation.
